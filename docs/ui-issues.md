# UI issues backlog (collected from the NAS preview)

Collecting mode: each issue the user reports (with a screenshot) is logged here and nothing is fixed until the user says "go".
Then the proposals are discussed and a final go is asked for before any change.

## Open

1. **Dashboard, Spending by category: legend overflows the panel.** The row of checkbox chips runs past the card edge (clipped at "Drinks", more categories hidden). The user finds the checkmarks overkill: drop them. Instead, clicking a donut slice focuses (highlights) that category, and clicking the color dot of a category in the list does the same (click again to clear). Related code: overview-page (hiddenSegments, toggleSegment, donut filters).
2. **Dashboard, Spending by month: tooltip label.** Hovering/highlighting a bar shows the short month ("Oct"); it should show the full month name and year ("October 2026"). Related code: overview-page tooltipCard / chart bars (bar.shortName).
3. **Dashboard, period picker: scroll drift and date fields.** The tab strip (This month ... Custom) can be scrolled sideways (a sliver of the next item shows next to "Custom"): it must not scroll on desktop widths. The From / To date fields should be visibly boxed, e.g. a gray border matching the quick-filter strip, so they read as inputs. Related code: overview/period-picker (overflow-x-auto on the tabs wrapper, input styling).
4. **Dashboard, receipts panel: shop icons.** The letter monogram badge (shop initial) should become the real shop logo, looked up from the shop name via logo.dev. Plan: a one-time script downloads about 20 popular European grocery chains (Lidl, Aldi, Carrefour, Auchan, Edeka, Rewe, Biedronka, Zabka, Kaufland, ...) into the app as static files, so no runtime requests and no key in the app. The user supplies the logo.dev API key (publishable/secret key to be used only for the download script, never committed). Display rule: in dark mode every logo gets a white border/outline, in white mode a black border, so white (or dark) logos stay visible. Unknown shops keep the monogram. Related code: shared-ui/shop-monogram (app-shop-monogram), used in overview and receipts table.
5. **Dashboard, Spending by month: empty space under the chart.** The card is stretched to the height of the category card beside it, but the chart keeps a fixed height, leaving a large empty block above the footer ("October 2026 / Open reports"). The chart should fill the available height (or the card should size to its content). Related code: overview-page chart card, ApexChart height.
6. **Receipts table (dark mode): row checkbox contrast.** On a highlighted (hovered) row the checkbox on the left nearly disappears (dark box on a slightly lighter row). It needs a clearly visible border/fill in dark mode, also when the row is hovered or selected. Related code: ui/checkbox (hlmCheckbox border/background tokens), receipts-table row hover.
7. **Receipts toolbar: alignment and date fields.** The From / To date fields, the filter, reset and more buttons sit at different heights/sizes (the date labels push the inputs out of line with the quick-filter strip and the Add Receipt button). Align the toolbar to one baseline and one control height. The From / To fields should use the same boxed gray-border design as proposed for the Dashboard (issue 3), so both pages share one period-picker look. Related code: overview/period-picker (shared by Dashboard and receipts table), receipts-table toolbar.
8. **Global: tab strips scroll (System Settings tabs, Logs, same as issue 3).** Root cause found: every pill strip uses overflow-x-auto (period-picker, shared-ui/filter-bar, shared-ui/tabs, system-settings tabs wrapper); setting overflow-x makes overflow-y auto too, so a 1px height overflow shows a vertical scrollbar with arrows next to the last tab. Fix once, globally: a shared "scroll-x" utility (overflow-y hidden, hidden scrollbar, optional edge fade only when content truly overflows, e.g. on phones). Applies to filter-bar, tabs, period-picker.
9. **System Settings: sections inside a card look flat.** Inside one card, sub-sections (Currency, Previews, Exchange rates) run together with only headings. Wants a clean, global, high-craft (fintech-style) treatment so separate things read as separate. Proposal: a shared "section" pattern used by every settings card: a muted inset panel (rounded-xl, 1px border at low contrast, subtle surface step instead of a shadow) with a small uppercase overline title and an optional one-line description, spaced on an 8px grid; read-only samples (Previews) get a quiet tabular-nums list with hairline dividers; actions (Save rates, Add currency) aligned in the panel footer. Implemented as one component/class set (rw-section) and reused in system settings, AI page, user preferences/profile and any card with several blocks. Also unify the exchange-rate rows (code, input, unit) into a compact aligned grid.
10. **AI page: fallback provider and model picker (feature).** (a) A fallback option: when the primary (local, LM Studio) fails or is unreachable, the receipt read retries with a fallback; for now Gemini only. The API already has primary + fallback processing settings (SystemSettings.fallbackReceiptProcessingSettingsId, tried in order by the product/receipt reads); the AI page only edits the primary. Needs a second card "Fallback (used when the first one fails)" with provider Gemini, key, model, and an on/off switch. (b) Model dropdown: yes, retrievable. With a Gemini API key the API can call GET generativelanguage.googleapis.com/v1beta/models?key=... (paged), keep models whose supportedGenerationMethods include generateContent, sort newest first, and the AI page shows them in a dropdown (with a refresh button and the free-text field kept as a fallback). New endpoint needed (admin only, key sent server-side, never logged), plus swagger + regenerated clients. Same idea could later list LM Studio models via its /v1/models.
    Decision (user): when both fail, the read waits and retries, but with a hard cap of 3 retries so tokens are never burned endlessly. Today: an outage (no AI / call failed) is retried hourly without counting as an attempt for up to 14 days; a bad answer is retried 3 times. Change: count every call that reaches a provider (primary then fallback = one attempt), cap at 3 attempts in total with spacing (e.g. now, +1 h, +6 h), then mark the product read / trip as FAILED with the last error and a visible "Read with AI" retry button (manual retry resets the counter). Applies to receipt product extraction, food classification and the trip comparison; the quick-scan receipt read keeps its own 3-try rule.
11. **Polish leftovers (language pass 3).** Seen in Polish: AI page ("A key is saved. Leave this empty to keep it." and the provider option "LM Studio (on a computer at home)"); table headers "Created At", "Updated At", "Actions", "Formats", "Detail" and the pager range "1 - 2 of 2" (App table pager, Users and Reports lists); report list cells ("No grouping", "Aggregate by Month", "Household" scope) and the starter report names; dates/times still in en-US ("10/21/26, 2:17 AM", "Oct 21, 2026": should follow the language locale, 24 h in Polish). Plan: a systematic sweep instead of spot fixes: list every string rendered from TypeScript constants (column headers, option labels, hints from keyHint(), report summaries) and route them through the translation service; register Angular locale data per language in the language registry (pl: dates, numbers) and make the appDate pipe use the active locale; add a spec that fails when a template/TS literal reachable from the UI has no Polish key (extractor script).
12. **Sidebar: "Ustawienia administratora" wraps and overlaps.** In Polish the Admin Settings label wraps to two lines and the expanded sub-item ("Kategorie") overlaps/touches it. The menu button needs a fixed one-line height with truncation (or a shorter Polish label such as "Administracja"), and the sub-menu needs proper spacing below the trigger. Check every language: labels must never wrap or collide. Related code: layout/sidebar (Admin Settings trigger, hlmSidebarMenuButton sizing), pl messages.
13. **About page: show only this project.** It still lists the original project links (receiptwrangler.io docs, upstream GitHub org, Reddit). Replace with the CartVibe GitHub repository (and the project page), the version/build date; keep a short credit line to Receipt Wrangler by Noah Hall (licence requirement in CLAUDE.md, NOTICE.md stays). Translate the labels ("Project", "Documentation"...). Related code: about/about.
14. **Tables (dark): row divider lines too bright.** In the Users and Reports lists the horizontal lines between rows are near-white, heavier than the high-craft hairline standard. Use a low-contrast border token (border/60) and a subtle hover step. Check header underline too. Related code: ui/table (hlmTr/hlmTd borders), app-table.
15. **Quick Scan dialog: footer buttons overlap the dashed drop zone; accept button color.** The confirm (check) and cancel (x) icon buttons sit on the bottom border of the dashed drop area. Give the dialog proper spacing (drop zone, then a footer row with its own padding and a hairline divider), and make the buttons proper labelled buttons (e.g. "Scan" primary, "Cancel" secondary). The accept button gets a green tint matching the decline button's red tint (soft emerald fill, emerald icon/text, same size and radius), disabled until a photo is chosen. Same footer pattern for every dialog (app-dialog-footer). Related code: receipts/quick-scan-dialog, shared-ui/dialog-footer.
16. **Photos the local model cannot read (HEIC, camera formats).** A HEIC (iPhone) or other camera-format photo is not processed by the local model (LM Studio / Qwen). Proposal: normalize every receipt image server-side before it is sent to any vision model: decode (HEIC/HEIF, PNG, WebP, TIFF, CMYK, very large JPEG), apply EXIF orientation, flatten alpha onto white, downscale so the long side is at most about 2048 px, and re-encode as baseline sRGB JPEG (quality about 85), sent as an image/jpeg data URL. PDFs keep the existing rasterization to JPEG. Done once in the AI image reader (services/receipt_processing.go readers, the same path for quick scan, product read and shopping trips) with the ImageMagick the image already has; the stored original stays untouched. Also accept HEIC/HEIF in the upload pickers and show a friendly error when conversion fails. Add Go tests with a HEIC and an oversized JPEG fixture.
