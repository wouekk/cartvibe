# UI issues backlog (collected from the NAS preview)

Collecting mode: each issue the user reports (with a screenshot) is logged here and nothing is fixed until the user says "go".
Then the proposals are discussed and a final go is asked for before any change.

## Open

1. **Dashboard, Spending by category: legend overflows the panel.** The row of checkbox chips runs past the card edge (clipped at "Drinks", more categories hidden). The user finds the checkmarks overkill: drop them. Instead, clicking a donut slice focuses (highlights) that category, and clicking the color dot of a category in the list does the same (click again to clear). Related code: overview-page (hiddenSegments, toggleSegment, donut filters).
2. **Dashboard, Spending by month: tooltip label.** Hovering/highlighting a bar shows the short month ("Oct"); it should show the full month name and year ("October 2026"). Related code: overview-page tooltipCard / chart bars (bar.shortName).
3. **Dashboard, period picker: scroll drift and date fields.** The tab strip (This month ... Custom) can be scrolled sideways (a sliver of the next item shows next to "Custom"): it must not scroll on desktop widths. The From / To date fields should be visibly boxed, e.g. a gray border matching the quick-filter strip, so they read as inputs. Related code: overview/period-picker (overflow-x-auto on the tabs wrapper, input styling).
4. **Dashboard, receipts panel: shop icons.** The letter monogram badge (shop initial) should become the real shop logo, looked up from the shop name via logo.dev. Plan: a one-time script downloads about 20 popular European grocery chains (Lidl, Aldi, Carrefour, Auchan, Edeka, Rewe, Biedronka, Zabka, Kaufland, ...) into the app as static files, so no runtime requests and no key in the app. The user supplies the logo.dev API key (publishable/secret key to be used only for the download script, never committed). Display rule: in dark mode every logo gets a white border/outline, in white mode a black border, so white (or dark) logos stay visible. Unknown shops keep the monogram. Related code: shared-ui/shop-monogram (app-shop-monogram), used in overview and receipts table.
5. **Dashboard, Spending by month: empty space under the chart.** The card is stretched to the height of the category card beside it, but the chart keeps a fixed height, leaving a large empty block above the footer ("October 2026 / Open reports"). The chart should fill the available height (or the card should size to its content). Related code: overview-page chart card, ApexChart height.
6. **Receipts table (dark mode): row checkbox contrast.** On a highlighted (hovered) row the checkbox on the left nearly disappears (dark box on a slightly lighter row). It needs a clearly visible border/fill in dark mode, also when the row is hovered or selected. Related code: ui/checkbox (hlmCheckbox border/background tokens), receipts-table row hover.
7. **Receipts toolbar: alignment and date fields.** The From / To date fields, the filter, reset and more buttons sit at different heights/sizes (the date labels push the inputs out of line with the quick-filter strip and the Add Receipt button). Align the toolbar to one baseline and one control height. The From / To fields should use the same boxed gray-border design as proposed for the Dashboard (issue 3), so both pages share one period-picker look. Related code: overview/period-picker (shared by Dashboard and receipts table), receipts-table toolbar.
8. **Global: tab strips scroll (System Settings tabs, Logs, same as issue 3).** Root cause found: every pill strip uses overflow-x-auto (period-picker, shared-ui/filter-bar, shared-ui/tabs, system-settings tabs wrapper); setting overflow-x makes overflow-y auto too, so a 1px height overflow shows a vertical scrollbar with arrows next to the last tab. Fix once, globally: a shared "scroll-x" utility (overflow-y hidden, hidden scrollbar, optional edge fade only when content truly overflows, e.g. on phones). Applies to filter-bar, tabs, period-picker.
9. **System Settings: sections inside a card look flat.** Inside one card, sub-sections (Currency, Previews, Exchange rates) run together with only headings. Wants a clean, global, high-craft (fintech-style) treatment so separate things read as separate. Proposal: a shared "section" pattern used by every settings card: a muted inset panel (rounded-xl, 1px border at low contrast, subtle surface step instead of a shadow) with a small uppercase overline title and an optional one-line description, spaced on an 8px grid; read-only samples (Previews) get a quiet tabular-nums list with hairline dividers; actions (Save rates, Add currency) aligned in the panel footer. Implemented as one component/class set (rw-section) and reused in system settings, AI page, user preferences/profile and any card with several blocks. Also unify the exchange-rate rows (code, input, unit) into a compact aligned grid.
