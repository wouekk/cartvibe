# CartVibe design: read before building any UI

High-craft fintech, monochrome zinc by default (Zinc is monochrome; Blue, Indigo, Emerald and Violet add an accent only), on spartan/ui + Tailwind 4. This file is the single description of the look; every screen, dialog and empty state follows it. Anything that looks sloppier than the screen beside it is not done.

The identity has priority over a request until the user says otherwise: if a request would change the look (new effects such as glass or blur, values off these scales, a new style direction), ask first, then fit the agreed values to the scales below. Adding a palette: `docs/themes.md`.

## Principles
- Tokens only: never write a hex/rgb in a component; add a token to *every* palette if one is missing.
- Separate surfaces with a surface step plus a 1px low-contrast hairline, not shadows or boxes inside boxes.
- Quiet hierarchy: small uppercase overlines, muted descriptions, one bold number.
- One control height per row (`h-control`: 36px under a mouse, 44px under a finger); toolbars sit on one baseline.
- Reuse the shared piece; fix a pattern once, globally. Never build a one-off.
- Design every state (hover, focus-visible, selected, disabled, loading, empty, error) in Day and Night.
- Phone first: it is used in the shop. No horizontal page scroll at 360px.

## Stack
Angular + spartan/ui helm (`src/ui`, alias `@spartan-ng/helm/*`, generated by `node tools/spartan-add.cjs <name>`) + Tailwind 4 (`src/tailwind.css`) + Geist + Lucide through `<app-icon name="material_name">` (map in `shared-ui/icon/icon-map.ts`) + Chart.js (canvas) through `app-chart`.
Banned: Angular Material, Bootstrap classes (`d-flex`, `col-*`, `mb-3`), `mat-*`, new SCSS variables from `variables.scss`, `$shadow-*`, ad-hoc colors, `:host {}` styling (use `host: { class }`), unlayered global CSS.

## Tokens (`src/themes/<palette>.css`, `zinc.css` is the base; mapped in `tailwind.css` `@theme inline`)
- Look = palette x mode, per browser. Palettes (`PALETTES` in `src/theme/themes.ts`, `data-palette` on `<html>`): Zinc (default, first in every picker), Blue, Indigo, Emerald, Violet. Modes: System, Day, Night (`dark` class on `<html>` drives `dark:`). Pickers: Settings → Theme (Appearance, Colour palette and Interface size cards) and the welcome; the header carries no theme control (it is set once, and a phone's header has no room for it). Accent palettes change only the primary, the focus ring and the sidebar primary; surfaces, status, charts and brand are the same in all.
- Surfaces: `bg-background` (canvas, zinc-50 / neutral-950), `bg-card` / `bg-popover` (white / zinc-900), `bg-muted` (+ `/30`, `/40` for inset steps), `bg-secondary`, `bg-accent` (a neutral hover/selected tint, not a brand colour), `bg-sidebar*`.
- Page background: plain `bg-background`. The project site's grid-and-glow canvas stays on the site, except behind the sign-in page (`.cv-auth-bg` in `tailwind.css`: the same hairline grid and spotlight, the glow in the brand emerald in every palette, no motion); it was tried across the whole app on 2026-11-02 and dropped. An empty state boxed straight on the page takes `bg-card`, like the report preview's.
- Text: `text-foreground`, `text-muted-foreground`, `text-card-foreground`, `text-primary-foreground`.
- Lines: every border defaults to `--border` (base layer). Hairlines: `border-border`, `border-border/70` (panels), `/60` (dividers), `/40` (list rows). Focus: `ring-ring/50`, `ring-3`.
- Primary: `bg-primary` is monochrome in Zinc (neutral-950 by day), near-white at night, and the hue in Blue / Indigo / Emerald / Violet (600-700 by day, 400 at night, with `text-primary-foreground` kept at 4.5:1). Hover `bg-primary/80`. `text-primary` (links, "blue" badge) must hold 4.5:1 on background, card and accent.
- Status: `text-destructive` / `bg-destructive/10`; `text-warning-text` (orange: rises, unhealthy, "to check"); `text-success-text` (green: falls, done); `bg-warning text-warning-foreground` (filled warning); `nutri-a..e` with `text-nutri-a..e-foreground` (health score only).
- Charts: `--chart-1..5` + `--muted-foreground` ("Other") via `readChartColors()` (`shared-ui/chart/chart-colors.ts`); spending bars: `colors.foreground` for every bar (black by day, white at night, never the accent primary), `colors.destructive` over goal, the selected month a bold foreground label. Grid `colors.border`, dashed 3. The donut's active slice slides 8px out of the ring while the others fade to 45%; the tooltip is our own HTML card on the theme tokens (`tooltipCard`).
- Brand: `--brand-*` only for the logo/icon/loader components. Never reuse them in UI. The wordmark's "Vibe" (`cartvibe-logo`) matches the project site: brand emerald in Zinc (`#16C976` at night, `#047857` by day, since the brand green is 2.1:1 on the light canvas), the palette's `--primary` in Blue, Indigo, Emerald and Violet.

## Scale
- Spacing: Tailwind 4px steps; gaps 2/3/4/6 (8/12/16/24px). Page gutter `p-4 sm:p-6`; content width `--page-max` 77.5rem (1240px; set once in the shell). Interface size (Settings → Theme, per browser, `INTERFACE_SIZES` in `src/theme/themes.ts`): Standard, Large 125%, Larger 150%, Largest 200%, written as a percentage on `<html>`, so browser zoom and the reader's own font size still work; never tie the root size to the window's width again. A screen 1920px or wider that never chose starts at the step it had under the old width rule (2560: 125%, 3840: 200%). From 1920px `--page-max` is 98rem, so a large size on a wide screen still fills the window. Sizes are in rem (no fixed `[Npx]` except 1-2px hairlines) so they scale; chart text uses `chartFontSize()`.
- Radius (`--radius` 10px): buttons/inputs `rounded-md` (8), field boxes/insets `rounded-lg` (10), cards/panels/dialogs `rounded-xl` (14), pills/counts `rounded-full`.
- Controls: buttons, inputs, selects, tab strips `h-control`; icon button `size-control`. The token (`--control-h` in `tailwind.css`) is 36px under a mouse and 44px on a coarse pointer, the platform touch size; never write `h-9` / `size-9` for a control. `size="sm"` stays h-8 for dense secondary actions. Row targets on touch lists `min-h-11`..`min-h-14` (`min-h-16` in Shop mode).
- Motion: `duration-150` default, 200ms for emphasis; enter = `animate-in fade-in-0` (+ `slide-in-from-bottom-2`). Always add `motion-reduce:` / `prefers-reduced-motion`; a base-layer rule in `tailwind.css` also stills every animation and transition under reduced motion (spinners and `.app-progress-indeterminate` only slow down). Press: buttons get `active:scale-[0.98]` from helm.

## Typography
- Font: Geist Variable (`--font-sans`). Headings 600, tight tracking (base layer).
- Page title `h1` (settings: `text-2xl`); card title `.cv-card__title` 17px semibold; panel `h2` `text-base font-bold`; body `text-sm`; description 13px muted (`.cv-card__desc`).
- Overline: `text-[11px] font-semibold uppercase tracking-wider text-muted-foreground` (or `.cv-section__title`). Table headers use the same.
- KPI: label `text-xs font-medium text-muted-foreground`, value `text-3xl font-bold`, sub-line `text-[0.8125rem] font-medium`.
- Money: `<app-money [value]>` (whole part bold, symbol/decimals `opacity-60` of the same color); `[display]="true"` on the Dashboard only. Digits `tabular-nums` (automatic in tables, `.tile`, `app-money`, charts).
- Inputs are 16px below 768px (no iOS zoom). Never translate data (money, dates, names); every UI string goes through `| t`.

## Building blocks (`src/shared-ui` unless noted)
- Settings page: `app-settings-page` (title, description, `[settingsActions]`, `[settingsTabs]`) > `app-settings-section` (card; `[sectionActions]`, `[sectionFooter]` with `class="cv-card__footer"`, `tone="destructive"`) > `.cv-section` rows. Lists: `app-settings-entity-list` around `app-table`. (`shared-ui/settings/`)
- Tabs / segmented filters: `app-settings-tabs` (also behind `app-filter-bar`, `app-tabs`). Period: `app-period-picker` (`overview/period-picker`).
- CSS components (`tailwind.css`): `cv-card*`, `cv-section*`, `cv-inset` (read-only muted block), `cv-list` (hairline key/value list), `cv-scroll-x` (sideways scroll, no scrollbar), `cv-scroll-y` (a Dashboard list scrolling under the mouse wheel, thin scrollbar; fine pointers only, never on touch), `cv-field-box*` (boxed labelled field), `cv-panel*` / `cv-tile` / `cv-tile-link` (Dashboard), `cv-pill-up` / `-down`, `cv-link`.
- List page header: `app-table-header` (+ `subtitle`); create: `app-add-button [buttonText]="'Add X'"`.
- Avatars: `app-avatar` (`src/avatar/`, `size` md / sm / xs) is a circle with the person's photo (`object-cover`) when
  they uploaded one, otherwise the first letter, white on their own colour or the primary pair. A household shows its
  icon on its colour, or its initial on the primary pair. Household colours are the 19 `--household-<name>` tokens (`GROUP_COLORS`: zinc, slate, then round the wheel red to rose, every theme palette included)
  with `--household-foreground` (`--household-light-foreground` on amber, yellow and lime), defined once in `zinc.css` like the status colours:
  deep with a white mark by day, light with a dark mark at night. Colour menus (households, and the avatar colour as each colour's deep `hex`) are `app-color-swatches`. The picker (`app-group-look-picker`) is two grids of
  `min-h-11` toggle buttons with `aria-pressed`, a default first. Photo buttons are native `<label>`s styled
  with `buttonVariants` (primary for the camera, outline for a file); *Remove photo* is `variant="destructive"`.
- Countdown columns (Days left on the warranties panel and page): right-aligned, bold, tabular, "Today" for 0, and
  `text-warning-text` within a week.
- Connection line (a shopping list's header, under its name, `text-xs`): a 6 px dot in the text's colour and one word,
  *Live* in `text-success-text`, *Reconnecting* muted, *Offline* in `text-warning-text`, then `cloud_upload` and the
  number of changes still waiting (the words are its tip and its screen-reader text). The same `cloud_upload`, muted,
  marks a row that has not been sent. Never a banner for it; the one notice above the list explains what happens to
  changes. A crossed-off row ends in the `xs` avatar of whoever crossed it off, after the amount.
- Buttons: `hlmBtn` (primary), `variant="outline|ghost"` for toggles/menus/icon rows, `variant="destructive"` (red) for every delete and remove: buttons, row icons, menu items (`hlmDropdownMenuItem variant="destructive"`) and the confirm button of a Delete / Remove dialog. Save = `app-submit-button`; Cancel = `app-cancel-button`, neutral `outline` (white by day, black at night), never red.
- Dialogs: `AppDialog` (`src/dialog/app-dialog.ts`) + `app-dialog-footer`; confirm with `ConfirmationDialogComponent`.
- Fields: `app-input`, `app-select`, `app-textarea`, `app-checkbox`, `app-datepicker`, `app-autocomlete`, `app-form-section [panel]`.
- Menus `hlmDropdownMenuTrigger`; tips `hlmTooltip` (the popover surface with a hairline, no arrow, not an inverted black box); toggles `hlm-switch`; badges `app-badge` (tones slate/blue/green); status `app-status-chip`; shops `app-shop-monogram` (a logo sits on a white tile with a `ring-border` hairline: the one allowed fixed colour, since logo art assumes white); toasts `SnackbarService`; loading `hlm-spinner`, `.app-progress-indeterminate`; required-empty `shakeInvalid()`.

## Patterns
- Page: header row (`h1` + muted context left, actions right, `flex-wrap gap-2`), then `flex flex-col gap-6`. Text flex children need `min-w-0`; headings `break-words`.
- Card: `rounded-xl border border-border/70 bg-card`; header `min-h-14 border-b border-border/60 px-4`; body `px-4 pt-3 pb-4`.
- Rows: `flex min-h-14 items-center border-b border-border/40 last:border-b-0`, hover `bg-muted/40`, trailing ghost icon button with `more_vert` menu. Amounts right-aligned, bold, tabular.
- Settings list rows (households, users, categories, tags, a household's members): `app-row-actions`
  (`shared-ui/row-actions/`) draws inline icon buttons (accent icons, a red `app-delete-button`) on a wider screen and one
  `more_vert` menu on a phone (below 768px, `ViewportService.isHandset`), never both. Every phone row menu is a
  `more_vert` menu; Delete stays red and confirmed at both widths.
- Selected card: `border-primary bg-accent/30 ring-1 ring-primary/20` + `aria-pressed`.
- Finished/archived card: `bg-muted/30 text-muted-foreground`, a `history` icon before the name, and its actions in a
  `more_vert` ghost icon button placed beside the card button (absolute, top right), never nested inside it. A group
  of them folds away behind a chevron toggle (`expand_more`, rotated when open) with its count, like Crossed off.
- Preview dialogs (recipe import): a muted title and count line, one `border-b border-border/60` bar for the controls
  (`app-settings-tabs` pills plus `size-control` outline icon buttons, all `h-control`), then `min-h-11` rows with a checkbox, the
  data text (`min-w-0 break-words`, never translated) and a right-aligned `tabular-nums` value; a reason to fall back sits
  in a `cv-inset` with an `info` icon. `app-dialog-footer [submitDisabled]` dims Save while nothing is selected.
- Unsaved changes: a Save with changes waiting takes `.cv-unsaved` (`tailwind.css`), a halo in `--ring` that breathes between 3 and 5px (still under
  reduced motion). `app-submit-button` adds it for an edit form (`mode` edit, or `[highlightUnsaved]`, which `app-form` sets when editing); a custom Save
  adds `[class.cv-unsaved]` from its own dirty state. Never on a disabled Save (nothing to save), an add form (nothing saved yet) or a focused button.
- Settings: always editable; Save in the card footer on the right, status text left (`cv-card__status`), dimmed while pristine (`[mode]="FormMode.edit"`). No floating save bar.
- Grouped lists in a dialog (the Dashboard's Other list): one `table-fixed` table, so the column header (sticky) and amounts line up from the first line to the last; each group opens with a `bg-muted/60` band (a surface step, not a rule) holding its name and subtotal, with a small gap before the next group.
- Dialog footer: hairline `border-t`, actions right: outline Cancel, primary Save. A confirmation's button names the action ("Delete", "Remove"), not "Confirm", and is red for those two.
- Empty: centered, `py-10`, icon in a `size-10 rounded-full bg-muted text-muted-foreground` circle, one `text-sm text-muted-foreground` line, then the page's own add button. Whole-page empty: same inside `rounded-xl border border-dashed`.
- Loading: render nothing or `–` placeholders until loaded (`isLoaded()`), spinner inline for actions; each panel loads and fails on its own. Error: toast via `SnackbarService`; field errors in `--destructive`.
- Toolbars: one `flex flex-wrap items-center gap-2` row, all `h-control`; strips in `cv-scroll-x`.
- Disabled: dimmed with `pointer-events: none` (no not-allowed cursor; user's decision).
- Phone: card rows become `cv-scroll-x snap-x` strips; grids `sm:grid-cols-2 lg:grid-cols-4`; side panels stack below `lg`; labels collapse to icons with `max-sm:sr-only`; no hover-only affordances.
- Phone navigation (below 768px): the tab bar (`layout/tab-bar`), stuck to the bottom as the last child of the page column: `bg-background`, a hairline on top, the safe-area inset below, five equal slots of `min-h-14` (a 20px Lucide icon over an 11px label, muted; the current page `text-foreground` semibold with `aria-current`). Scan sits in the middle in a `size-12 rounded-full bg-primary` circle raised 20px with a `ring-4 ring-background` cut-out; More opens the sidebar sheet. It hides while a text field has the focus. The header then shows the household (`xs`-row avatar and name) where the sidebar button is on a wider screen.
- Phone lists: a table never scrolls sideways on a phone. `app-table` draws each row as a card (`px-4 py-3`, hairline between): title `font-medium`, a muted subtitle, the right-hand side (the first value bold: the amount), the row's one `more_vert` menu, then labelled details in `text-xs`; sorting is one `Sort by` select and a direction button above the cards. A column places its cell with `phone` (`table-column.interface.ts`). A receipt's product lines follow the same shape (name and amount first, *No amount* in `text-warning-text`, chips below, one menu).
- List switcher: chips above the open list (`h-control rounded-full border`, name plus a count pill, the open one in the Selected style with `aria-pressed`), a `cv-scroll-x snap-x` strip bleeding to the page gutter on a phone, wrapping from `sm`.
- Shop mode (shopping list): the open list alone. No page header, switcher, trips or finished lists; rows `min-h-16` with an 18px name; an outline *Leave Shop mode* button (`close`) in the list's header.
